# 설계: 토큰 소진 시 자동 대기·재개 (Olympus)

- 날짜: 2026-07-03
- 상태: 설계 승인됨 (구현 계획 대기)
- 대상: `~/projects/olympus` (bash 오케스트레이터)

## 1. 문제

올림푸스는 각 역할 호출을 `claude -p`(헤드리스) 프로세스로 실행한다(`run.sh`의 `metis()` run.sh:131, `worker()` run.sh:162). 무인 장시간 실행 중 **Claude Code 사용량 한도(5시간 롤링/주간)**에 걸리면 `claude` 호출이 실패한다.

현재 코드는 **그 실패를 감지하지 못한다**: `metis()`/`worker()`가 `claude -p`의 종료코드를 검사하지 않고(`|| ...` 없음), `run.sh`는 `set -e`도 아니다(run.sh:11). 따라서 토큰이 떨어지면 파이프라인이 조용히 다음 단계로 진행해 헛돌거나(`MAX_ROUNDS` 소진 → "예산 소진 사람 개입") 무의미한 상태를 만든다.

**원하는 동작**: 소진을 감지하면 **대기**하다가, 한도가 리셋되면 **중단된 그 자리에서 자동으로 계속**한다. 사람 개입 없이.

## 2. 목표 / 비목표

**목표**
- `claude -p` 호출이 사용량 한도로 실패하면 감지한다.
- 한도가 풀릴 때까지 대기한 뒤, 실패한 **동일 호출을 재시도**해 그 자리에서 계속한다.
- macOS와 Windows(Git Bash/WSL) 양쪽에서 동일하게 동작한다.
- 대기 중 토큰 비용은 무시할 수준(≈0)으로 유지한다.
- 실행 중인 `run.sh` 프로세스 안에서 자동 처리한다(A안).

**비목표 (이번 범위 밖)**
- 프로세스가 죽거나 머신이 완전 종료/재부팅돼도 살아남는 외부 supervisor(launchd/스케줄러 자동 재실행) — 이는 후속 "B안"으로 분리한다.
- 429/529 등 일시적 용량 오류 처리 — Claude Code CLI가 자체 재시도한다(§5 참조). 우리는 손대지 않는다.
- 리셋 시각의 정밀 예측/타임존 완벽 파싱 — §4의 자기교정 루프로 불필요.

## 3. 감지 (사실 근거)

Claude Code 2.1.199 기준, 조사로 확인된 동작(📄 공식 문서):

- **사용량 한도**는 stderr에 사람이 읽는 문자열로 출력된다:
  - `You've hit your session limit · resets 3:45pm`
  - `You've hit your weekly limit · resets Mon 12:00am`
  - `You've hit your Opus limit · resets 3:45pm`
  - → 감지 패턴: 출력을 `2>&1`로 합쳐 캡처하고 **`You've hit your`** 를 매칭.
- **종료코드는 오류 유형별로 문서화되어 있지 않다**(전부 1로 추정, 미검증). → 종료코드가 아니라 **출력 패턴**으로 판정한다.
- `--output-format json`을 써도 구조화된 reset/error 필드는 없다. → 정규식으로 긁는다.
- **사용량 한도로 거부된 요청은 추론 전 게이트에서 막혀 토큰 0 소비**, 재시도가 리셋 시각을 늦추지도 않는다. → 대기 중 재시도는 사실상 무료.
- (대조) **429 레이트리밋은 입력 토큰이 카운트**된다(프롬프트 파싱 후 거부). → 체크에 큰 프롬프트를 재전송하면 최악의 경우 입력 토큰 소모. §6의 프로브 설계로 회피.

## 4. 대기 전략 — 파싱리스 자기교정 루프 (크로스플랫폼 핵심)

기존 코드에는 `date` 산술 연산이 **한 곳도 없다**(`date +포맷`만 사용). 리셋시각 파싱(`date -d`/`date -j`)을 도입하면 올림푸스 최초의 BSD/GNU 분기가 되어 이식성이 깨진다. 이를 피하기 위해 **파싱에 의존하지 않는** 루프를 기본으로 한다.

```
claude_guarded(<실제 claude 인자들>):
    output = run(claude <실제 인자들>) 2>&1 로 캡처 (동시에 로그로 tee)
    if output 에 "You've hit your" 없음:
        return (성공이든, 한도-아닌 실패든 — 호출부가 기존대로 처리)
    # 사용량 한도 감지됨 → 프로브 대기 루프로 진입
    notify_once("⏸ 토큰 소진 — 대기 후 자동 재개")     # best-effort (§7)
    loop:
        wait = compute_wait(last_output)                 # §4.1
        total_waited += wait; if TOKEN_MAX_WAIT_SEC>0 and total_waited>cap: return 실패
        sleep(min(wait, TOKEN_WAIT_CHUNK_SEC))
        last_output = run(probe) 2>&1                    # §6: 극소 입력 프로브
        if last_output 에 "You've hit your" 없음:
            break                                        # 한도 풀림
    return run(claude <실제 인자들>)                     # 무거운 실제 호출을 그제서야 1회 재개
```
> 즉 **최초 1회는 실제 호출**을 시도하고, 한도에 걸린 뒤부터의 주기적 "아직 한도인가" 확인은 **§6 프로브**로만 한다. 실제(무거운) 호출은 프로브 통과 후 한 번 재개된다.

- 한도 걸린 호출은 **빨리 실패**(토큰 0)하므로, 주기적으로 다시 시도해 "아직 한도인가"를 확인하는 비용이 저렴하다.
- 시각을 조금 잘못 계산해 일찍 깨어나도, 다음 반복이 새 한도 메시지를 다시 읽고 또 대기 → **자기교정**. 정밀 파싱 불필요.

### 4.1 `compute_wait(output)` — best-effort, 실패해도 안전
1. 출력에서 `resets ...` 뒤 시각 문자열을 정규식으로 추출 시도.
2. 파싱 가능하면(§4.2) `리셋 - 현재 + TOKEN_RESET_BUFFER_SEC` 초를 계산.
3. 파싱 불가/음수/추출 실패면 → `TOKEN_RETRY_SEC`(기본 1200초=20분).
4. 어느 경우든 **한 번의 sleep을 최대 청크(예 1800초=30분)로 제한**한다. 30분보다 오래 기다려야 하면 30분씩 나눠 자며 매 청크 후 다시 프로브(§6)한다 → 시각 오차·머신 시계 드리프트에 견고.

### 4.2 리셋시각 파싱 (선택적 "가속" — 없어도 됨)
- `date --version` 이 성공(GNU: WSL/Git Bash) → `date -d "$reset_str"` 로 epoch 계산 시도.
- 실패(BSD: macOS) → `date -j -f "%I:%M%p" ...` 형태로 시도.
- **어느 쪽도 실패하면 조용히 §4.1-3 폴백**으로 떨어진다(에러 아님). 파싱은 순전히 "덜 자주 깨어나게" 하는 최적화일 뿐, 정확성의 의존 대상이 아니다.

## 5. 429/529 분리 — CLI에 위임

- Claude Code는 429(레이트리밋)/529(과부하)/네트워크 오류를 **자체 지수백오프로 자동 재시도**한다(기본 10회). `CLAUDE_CODE_RETRY_WATCHDOG=1` 환경변수를 켜면 무인 실행에서 이들을 무한/장시간 재시도한다.
- → `run.sh` 실행 환경에 **`CLAUDE_CODE_RETRY_WATCHDOG=1`** 을 export한다(env라 플랫폼 무관). 우리 대기 루프는 **사용량 한도만** 담당하고 429/529는 CLI가 삼킨다.

## 6. 프로브 기반 체크 (토큰 비용 ≈ 0 보장)

- §4의 재시도에서 **무거운 역할 프롬프트(role+spec+state)를 통째로 재전송하지 않는다.** 대신 **가벼운 프로브**로 한도 해제 여부만 떠본다:
  - `claude -p "ok"`(극소 입력) + 실제 호출과 **동일한 `--model`**(모델별 한도 "Opus limit"을 정확히 반영하기 위해).
  - 프로브 출력에 `You've hit your`가 있으면 여전히 한도 → 대기 지속.
  - 프로브가 통과하면 → 원래의 무거운 실제 호출(`metis`/`worker`)을 **딱 한 번** 실행.
- 사용량 한도(주 케이스)는 원래 토큰 0이지만, 만일의 429 상황에서도 프로브는 극소 입력이라 비용이 무시할 수준. 로그도 깔끔.
- 구현상: `claude_guarded`는 실제 호출을 감싸고, 한도 감지 시 **프로브 루프**로 들어갔다가 프로브 통과 후 실제 호출을 재개하는 형태.

## 7. 알림 (best-effort)

- 일시정지 진입 시 폰으로 1회 알림: `⏸ 토큰 소진 — (리셋 ~HH:MM 추정) 자동 재개 예정`. 재개 시 선택적으로 `▶ 재개`.
- 기존 `notify.py`/`remote.sh` 인프라 재사용. 알림 설정(`.env.local`)이 없으면 **조용히 스킵**(파이프라인은 그대로 대기·재개). 알림 실패가 대기를 막지 않는다.

## 8. 구성 (config.sh 신규 노브)

| 변수 | 기본 | 의미 |
|---|---|---|
| `TOKEN_WAIT` | `1` | 이 기능 on/off. 0이면 기존처럼 감지 없이 진행. |
| `TOKEN_RETRY_SEC` | `1200` | 리셋시각 파싱 실패 시 재시도 간격(초). |
| `TOKEN_RESET_BUFFER_SEC` | `60` | 파싱된 리셋시각에 더할 여유(초). |
| `TOKEN_WAIT_CHUNK_SEC` | `1800` | 한 번의 sleep 최대 길이(초). 이보다 길면 나눠 자며 재프로브. |
| `TOKEN_MAX_WAIT_SEC` | `0` | 총 누적 대기 상한(초). 0=무제한. 초과 시 실패 반환. |
| (env) `CLAUDE_CODE_RETRY_WATCHDOG` | `1` | run.sh가 export. 429/529를 CLI가 무한 재시도. |

## 9. 컴포넌트 / 파일

  - 단일 책임: "claude 호출을 사용량 한도에 견디게 감싼다". 순수 bash, GNU/BSD 전용 플래그 없음, bash 3.2(macOS 기본) 호환 구문만.
- **`run.sh` 수정**: `metis()`/`worker()`의 인라인 `claude -p ...` 를 `claude_guarded ...` 경유로 교체. 상단에서 `resilience.sh` 소스 + `export CLAUDE_CODE_RETRY_WATCHDOG=1`(TOKEN_WAIT=1일 때).

## 10. 알려진 한계 (명시)

- **A안 범위**: 대기는 **실행 중인 `run.sh` 프로세스 안**에서 일어난다. `sleep`은 벽시계 기준이라 맥/PC가 잠자기→깨어나도 남은 시간만큼 이어 대기하지만, **터미널을 닫거나 프로세스가 죽으면(로그아웃·강제종료·재부팅) 유실**된다. 그 경우 사람이 `bash run.sh`를 다시 실행하면 durable 상태에서 이어진다(기존 재개 경로).
- 클램셸(뚜껑 닫힘) 절전 등으로 프로세스가 강제 종료되는 환경은 후속 B안(외부 supervisor 자동 재실행) 대상.

## 11. 테스트 (크로스플랫폼)

- 스텁 `claude` 스크립트: 호출 카운터 파일을 두고 **1회차엔 `You've hit your session limit · resets 3:45pm`+비0 종료, 2회차엔 정상 종료**를 흉내낸다.
- `sleep`을 목킹(no-op 또는 기록만)해 실제로 안 자게 한 뒤, `claude_guarded`가 **한도 감지 → 대기(호출 기록) → 재시도 → 성공 반환**하는지 검증.
- 프로브 경로: 프로브가 1회 한도 후 통과 시 실제 호출이 그제서야 1번 불리는지 검증.
- 파싱 폴백: 파싱 불가한 리셋 문자열에도 `TOKEN_RETRY_SEC`로 대기하고 재시도하는지 검증.
- 순수 bash로 작성해 macOS·Git Bash·WSL에서 동일 통과.

## 12. 수용 기준

- `TOKEN_WAIT=1`에서, 스텁이 한도를 뱉으면 `claude_guarded`가 대기 후 재시도해 최종 성공을 반환한다(위 테스트 green).
- 한도 감지가 **출력 패턴** 기반이고 종료코드에 의존하지 않는다.
- 새 코드에 GNU/BSD 전용 명령·플래그가 없다(리셋 파싱은 감지 후 폴백 보장).
- `TOKEN_WAIT=0`이면 동작이 기존과 동일하다(회귀 없음).
- 기존 `test/` 스위트 green 유지.

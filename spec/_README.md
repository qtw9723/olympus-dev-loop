# spec/ — 기획서 폴더 (입력)

**프로젝트마다 하위 폴더 하나**를 만들어 그 안에 기획 문서(`*.md`)를 넣는다.
예: `spec/MyApp/00-개요.md`, `spec/MyApp/10-기능.md`, `spec/MyApp/20-API.md` …

`bash run.sh` 실행 시 자동으로:
1. `_`로 시작하지 않는 **첫 서브폴더**를 프로젝트로 인식(폴더명 = 프로젝트명).
2. `$PROJECTS_DIR/<폴더명>`(기본 `~/projects/<폴더명>`)에 **대상 repo를 자동 생성**(git init + 범용 `verify.sh` 게이트 설치).
3. 그 폴더의 문서들을 기획자(메티스)가 분석·분해해 개발.

→ **사용자는 그냥 `spec/<이름>/`에 기획서를 넣고 `bash run.sh`** 하면 된다.

새 프로젝트로 바꿀 땐: 옛 폴더 치우고 새 폴더 넣기 + `bash reset.sh`(상태 초기화).
한 번에 하나의 프로젝트 폴더만 두는 걸 권장(여러 개면 이름 오름차순 첫 폴더 선택).

## ⚠️ 대상 repo 지정 — `run.env` (기존 repo·버전 폴더는 필수)

위 기본 동작은 **폴더명 = repo명 = 새로 만들 greenfield 프로젝트**를 전제한다.
하지만 **기존 repo를 수정(brownfield)** 하거나 **폴더명이 repo명과 다를 때**(예: 버전별 `spec/<repo>-vX.Y.Z/`)
이 기본값은 위험하다: `TARGET_REPO`가 `$PROJECTS_DIR/<폴더명>`으로 잡혀 **엉뚱한 빈 폴더**를 대상으로 삼는다.

> 🔥 실제 사고(2026-07-09): `spec/my-app-v1.0/` 로 실행하니 대상이 빈
> `~/projects/my-app-v1.0`(실제 repo는 `-v0.4.0` 없는 `my-app`)로
> 잡혀, 세션이 빈 폴더만 보고 개발을 못 했다. UI/큐 실행은 세션 시작 시 작업 허용 디렉토리가
> 고정되므로, 실행 중 권한 승인으로는 못 고치고 **재기동밖에 답이 없었다.**

→ 그래서 **greenfield가 아니면 반드시 `spec/<프로젝트>/run.env`** 에 대상·브랜치·게이트를 못박는다.
`run.sh`는 이 파일을 **자동 로드**하므로(UI·큐로 실행해도 적용), "그냥 실행"해도 올바른 repo/브랜치로 잡힌다.
우선순위: **명시적 env > run.env > config.sh 기본값/폴더명 추측**.

`run.env` 템플릿(그대로 복사해 값만 교체):
```bash
# spec/<프로젝트>/run.env — run.sh가 자동 로드
TARGET_REPO="$HOME/projects/<실제-repo>"    # ← 반드시 "존재하는" repo 절대경로 (폴더명과 달라도 됨)
GIT_BRANCH="feat/vX.Y.Z-..."                    # 작업 브랜치(없으면 생성, 있으면 체크아웃)
AUTO_MERGE=0        # dev 개발: main 자동 머지 금지(프로덕션 머지는 별도 수동 절차)
DEPLOY_ON_DONE=0    # dev: 자동 배포 없음
REMOTE=1            # 승인·질문을 폰/메일로 원격 처리
VERIFY_CMD="npm run build && deno test --no-check --allow-env --allow-net <테스트경로들>"
```

### 등록 전 프리플라이트 체크 ("그냥 실행"이 문제없게)

새 기획서를 큐/UI에 올리기 전에 아래를 한 번씩 확인하면, 위와 같은 재기동·중단이 재발하지 않는다.

- [ ] **대상 repo 실재**: `run.env`의 `TARGET_REPO`가 실제 존재하는 repo인가 — `ls "$TARGET_REPO/.git"`
- [ ] **브랜치 확인**: `GIT_BRANCH`가 의도한 dev 브랜치인가(없으면 생성됨, 있으면 체크아웃됨)
- [ ] **게이트 그린**: `VERIFY_CMD`를 repo에서 **직접 한 번 돌려 통과(green)** 하는가 — 통과 못 하면 Builder↔Critic 루프가 절대 green에 못 가 예산만 소진한다
- [ ] **verify 전제도구 설치**: `deno`/`node`/`npm` 등 `VERIFY_CMD`가 쓰는 도구가 이 기기에 있는가 — `which deno node npm`
- [ ] **의존성 자가 치유**: node 프로젝트면 `predev`/`prebuild`에서 설치 완주 여부를 확인(`node_modules/.package-lock.json` 부재 시 `npm ci`)하도록 해 둔다 → 릴리스 중 설치가 중간에 죽어 반쪽으로 남아도 다음 실행이 자동 복구(안 해두면 `sh: vite: command not found`로 verify가 계속 실패)
- [ ] **잔재 상태 정리**: 완전히 새 기획이면 `bash reset.sh <프로젝트>`로 초기화. 단, **이전 요구사항 분석을 이어서** 진행할 거면 `reset.sh` 금지(분석 결과가 지워져 전면 재분석 강제됨). 상태가 `needs_clarification`으로 멈춰 있으면 재실행 시 기획자(M0)가 재분석해 덮어쓴다.
- [ ] **기존 규약 확인**(아래 참조): 대상 repo의 주요 규약을 스펙에 명시하거나, `CLAUDE.md`/`AGENTS.md`에 있음을 확인

### 🔑 기존 프로젝트 이어서 작업 — 규약 확인·준수 (brownfield 가장 중요)

기존 repo를 이어서 개발할 땐, 신들(기획자·생성자·비평가)이 **그 프로젝트의 주요 규약을 확인하며 작업**해야 한다.
규약을 어기면 verify(테스트/빌드)가 green이어도 **결함**이다 — 예컨대 프로덕션 환경을 건드리거나, 하드코딩 금지 원칙을
깨거나, 네이밍/버전/브랜치 규칙을 무시하는 것.

- **규약은 repo가 소유한다**: 대상 repo의 `CLAUDE.md`·`AGENTS.md`·`README`·`docs/`·`ROADMAP` 등에 있는
  코딩·아키텍처·**환경(dev/prod)**·마이그레이션·네이밍·버전·브랜치·커밋 규약. (Claude Code는 대상 repo의
  `CLAUDE.md`를 자동 로드하지만, `AGENTS.md`·`docs/` 등은 자동 로드되지 않으니 **중요하면 스펙에서 명시적으로 가리켜라.**)
- **스펙 작성자가 할 일**: 기획서에 "이 repo의 `CLAUDE.md`/`AGENTS.md` 규약을 준수한다"를 한 줄 박고,
  특히 **놓치면 안 되는 규약**(예: "모든 작업은 dev 환경에서", "생성 규칙 하드코딩 금지·데이터구동",
  "머지 시 전체 마이그레이션·머지 후 dev 리셋")은 스펙 본문에 **다시 명시**한다. 규약이 스펙과 충돌하면 규약이 우선.
- **파이프라인이 강제하는 것**: 기획자(메티스)는 brownfield에서 구조·규약을 먼저 파악하고, 생성자(builder)는 구현 전
  규약 문서를 훑어 준수하며, 비평가(critic)는 규약 위반을 green이어도 결함으로 반려한다(각 `roles/*.md`에 명문화).

## 토큰 소진 자동 대기·재개 (무인 실행 안심)

장시간 무인 실행 중 Claude Code **사용량 한도**(5시간/주간)에 걸려도, 올림푸스가 **감지 → 리셋까지 대기 → 그 자리에서 자동 재개**한다. 기본 켜짐이라 **평소엔 신경 쓸 필요 없다** — 그냥 `bash run.sh` 하고 두면 한도에 걸려도 알아서 기다렸다 이어서 개발한다. (상세: 저장소 `README.md` "토큰 소진 자동 대기·재개", 구현 `resilience.sh`)

- **끄기**: `TOKEN_WAIT=0 bash run.sh` (그러면 예전처럼 한도 시 그냥 실패).
- **대기 간격 조정**(선택, 초): 리셋시각 파싱이 안 되는 환경(예: macOS)에선 `TOKEN_RETRY_SEC`(기본 1200=20분)마다 재확인한다.
  ```bash
  # 예: 10분마다 재확인, 총 대기 상한 없음(무제한)
  TOKEN_RETRY_SEC=600 bash run.sh
  ```
- 그 밖 노브: `TOKEN_RESET_BUFFER_SEC`(60) · `TOKEN_WAIT_CHUNK_SEC`(1800) · `TOKEN_MAX_WAIT_SEC`(0=무제한). 값은 `config.sh`나 env로 지정.
- 대기 중 **토큰 소비 ≈0**(한도 거부는 추론 전 게이트라 무료). 429/일시적 과부하는 CLI가 자동 재시도.
- ⚠ **한계**: 대기는 실행 중인 `run.sh` 프로세스 안에서만 일어난다. 잠자기→깨어남은 견디지만 **터미널을 닫거나 프로세스가 죽으면 유실** → 그땐 `bash run.sh`를 다시 실행하면 상태(state/)에서 이어진다. (macOS 클램셸 절전 등으로 프로세스가 강제 종료되는 경우는 아직 자동 재실행 안 됨)
